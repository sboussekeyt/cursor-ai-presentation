Context Engineering (1/3)

Gérer l'Absence de Mémoire : Stratégies de Persistence

⚠️ Le Problème : Pas de Mémoire Persistante

🔄
Stateless

Les LLMs n'ont pas d'état persistant entre les sessions

🆕
Nouveau Contexte

Chaque conversation démarre avec un contexte vierge

💥
Perte d'Informations

Les connaissances du projet disparaissent entre sessions

📝 Solution 1 : Fichiers Markdown (.md)

Stocker le contexte dans des fichiers versionnés avec le code

project/
├── .cursorrules          # Règles globales du projet
├── CLAUDE.md             # Instructions pour Claude
├── docs/
│   ├── architecture.md   # Contexte architectural
│   └── conventions.md    # Standards de code
└── src/
    └── ...
  • .cursorrules : Règles automatiquement chargées par Cursor
  • CLAUDE.md : Instructions spécifiques au projet
  • docs/ : Documentation technique et architectural

📎 Solution 2 : Context Files

Référencer dynamiquement des fichiers dans le contexte

📄
@filename

Inclure un fichier spécifique : @components/Button.tsx

📁
@folder

Inclure tout un répertoire : @src/utils/

🌐
@web

Récupérer docs externes : @https://react.dev/docs

🔌 Solution 3 : MCP (Model Context Protocol)

Connecter des serveurs de contexte externes

  • Serveurs externes pour enrichir le contexte
  • Bases de connaissances spécialisées
  • Context7 pour docs officielles
  • APIs tierces pour données en temps réel
