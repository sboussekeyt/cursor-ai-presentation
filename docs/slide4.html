Context Engineering (2/3)

Comprendre les Tokens : Optimiser la Fenêtre de Contexte

🔤 Qu'est-ce qu'un Token ?

Unité de traitement du texte par le LLM (~4 caractères en anglais, ~2-3 en français)

"Hello"
1 token
"Bonjour"
2 tokens
(Bon + jour)
"const x = 10;"
5 tokens

🪟 La Fenêtre de Contexte (Context Window)

Quantité maximale de tokens que le modèle peut traiter simultanément

Exemple : 200k tokens
System
5k
Files
50k
Chat History
100k
Output
45k
System Prompt : Instructions de base
Files : Code et docs inclus (@)
Chat History : Conversation
Output Buffer : Réponse générée

⚠️ Problème : Dépassement de Contexte

❌
Erreur Commune

"Context length exceeded" - Le contexte dépasse la limite

🧠
Perte de Mémoire

Le LLM "oublie" le début de la conversation

💸
Coût Croissant

Plus de tokens = facture plus élevée

🗜️ Stratégies de Compression

✂️
Résumé

Condenser l'historique en résumés concis des conversations précédentes

🎯
Sélection

N'inclure que les fichiers strictement pertinents pour la tâche actuelle

🗜️
Compression

Reformuler le contexte de manière plus concise sans perte d'information

🔄
Rotation

Archiver les conversations anciennes, garder seulement le contexte récent

📊 Distribution Optimale des Tokens

5% System Prompt
30% Files & Docs
50% Chat History
15% Output Buffer
